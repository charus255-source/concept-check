How I built this

Concept Check started in my notebook. These are my original handwritten notes, and what each idea became in the app.

1 · Draw the line

Who does what

My notes said

  • The browser sends the explanation to my backend.
  • The API key stays on the backend.
  • The LLM finds the recited sentence and writes a follow-up question.
  • The database keeps the learner's history.
  • No-go: the LLM deciding on its own that the learner understands.

What it became

  • Same line. The browser only ever talks to my backend.
  • Keys live in server settings, never in code or the browser.
  • The AI may only quote the learner's words and ask exactly one question. The code rejects anything else.
  • Every explanation, follow-up and answer is saved, with when it happened.
  • The no-go is enforced in code: Python grades each case against a reviewed answer key. The AI never decides a result.
2 · Lock the data

What gets stored

On paperIn the appWhy it changed
learnerlearners (id, learner_name)Same idea. The name is a random label, never a real name: store the least.
ideaThe list of concepts in the codeA fixed list that never changes at runtime, so code decides it.
golden_pairscases (case question, reviewed answer)Same idea, renamed. 30 reviewed cases, three per concept. The app refuses to grade a case whose text has changed.
recital_sentencegaps (the follow-up question), with the recited sentence saved on the attemptA "gap" is the weak spot the follow-up targets; a learner's retry points back to it.
attempts with attempt_type and resultattempts with event_type, passed, rule version and case fingerprintPractice and graded answers are kept apart, and every grade records which rules gave it. The database allows one graded answer per learner per case.
3 · Watch them use it

Tested with real people

Two classmates who had not seen the app tried it. What they did changed it:

  • "There is no feedback on answers." Now every result shows what was right, what is missing, and a model answer, and a Not yet leads to "Explain it again".
  • "I couldn't understand why my answer was incorrect." That answer was actually right; the checker was too strict. I exported every real answer, labelled each one, and measured: the checker wrongly failed 5 of 5 correct answers. After fixing it with what learners really wrote: 0 of 5, with no wrong answer getting through.
